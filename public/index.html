        03
        
No coordinator. No database.

        // the path of one request
      

      
A seed is how a new node gets in. After that, peers find each other.


      
    
        
  1. agentPOST /v1/chat/completions
    2. 
        
  2. gateway127.0.0.1:7778Your own model stops here: no peer, no receipt.
    3. 
        
  3. findgossip, then the DHT
    4. 
        
  4. linkdirect or relay
    5. 
        
  5. serving nodequeue, then --upstream
    6. 
        
  6. answertokens stream back
    7. 
        
  7. receiptboth sides sign, then it gossips
    8. 
      


      

        

          
Find each other

          
A DNS seed for first contact, then gossip and a Kademlia DHT.

        

        

          
Get through NAT

          
A relay carries the first bytes. Hole punching goes direct when routers allow it. Transport is encrypted.

        

        

          
Stream the answer

          
Your gateway speaks OpenAI and Anthropic, picks a free slot, or queues.

        

        

          
Count the work

          
Client and server both sign a receipt. Anyone can count the credits.

        

      


      

        

          
Relay, then direct

          
first   you ──▶ relay ──▶ peer

then    you ───────────▶ peer

          
If the routers do not allow it, the request stays on the relay.

        

        

          
One receipt

          
job  model  client  server
prompt_tokens  completion_tokens
output_sha256  ts
credits = prompt/4 + completion
client_sig  server_sig

          
Not verified: that the named model ran, or the token counts.

        

      


      
Still central // not in the request path

      

        
root key

        
One account sits at the top of the invite tree. Its address is built into the binary.

        
auto-update

        
Nodes install new releases from one GitHub repository, signed with keys built into the binary. --auto-update=false turns it off.

        
auditor

        
--audit uses a node the maintainers run by default. --auditor replaces it.

        
KV

        
A GitHub workflow writes this site's map to Cloudflare KV every ten minutes. The key expires one hour after the last write.

        04
        
Features

        // all in the one binary
      

      

        
Two APIs
OpenAI and Anthropic requests on one local port.

        
bitllm top
A live view of your node in the terminal.

        
Self-update
Updates only to a release signed with a key in the binary. Restarts when idle, or at the next start on Windows. --auto-update=false turns it off.

        
Credits
Every job you serve earns credits.

        
--location
Opt in to the map with a coarse cell of about 156 km.

        
--audit
Opt-in spot checks on the peers that answer you.

      

    


    

      

        05
        
A name is the model, not the machine.

      

      
Two machines with one name are interchangeable. If one stops answering, the gateway tries another.


      

        
Qwen/Qwen3.8-Flash-Next
├─ host a   stops answering
└─ host b   the gateway tries this one
// no failover after the first byte

      


      

        

          
Use the Hugging Face id

          
Qwen/Qwen3.8-Flash-Next, exactly as published. Hosts of the same repo match without a registry.

        

        

          
Name the actual weights

          
For a quant or fine-tune, add a suffix: ...-fp4-alesha. One name, one set of weights.

        

        

          
Just serve it

          
Any stable id works, with no registration. Models you add later appear without a restart.

        

      

    


    

      

        06
        
Invite-only, in the BitTorrent sense.

      

      
No account needed to try it. Membership decides who gets a free slot first.


      
    
        
  1. i
    An invite gets you served on any free slot. Uninvited nodes are served only when a server is idle, unless its owner opens it to everyone.
    2. 
        
  2. ii
    There is no daily quota by default. A server owner can set one.
    3. 
        
  3. iii
    Sharing makes you a contributor: 10 invites instead of 3 once your nodes have served, and no quota on a server that asked your node for a job in the last 7 days.
    4. 
      


      

        
root                 unlimited invites
└─ member            3 invites
   └─ has served     10 invites

      


      

        
Invites are signatures
An Ethereum account signs an invite and nodes gossip it. A root can revoke an account. It and everyone it invited are then served like uninvited nodes.

        
The server reads the prompt
Like any inference provider. Do not send secrets. Peers can learn your IP from a direct connection or from the addresses hole punching sends; use a VPN if that matters.

        
Nothing is verified yet
A node can claim a model it does not serve. Audits are opt-in spot checks, not proof of weights. What credits will be worth is not decided yet.
