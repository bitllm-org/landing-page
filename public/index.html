02 join

Use it, or add a GPU

The same binary is the client, the server and the relay. You choose which hat it wears with flags; the network topology takes care of the rest.

a / use

Point your agent here

Install, run, open 127.0.0.1:7778. The page lists every model online, gives a snippet for Claude Code, Cline, Aider or any OpenAI/Anthropic client, and sends a test message.

b / share

Share a local server

Already run vLLM, SGLang, llama.cpp, Ollama or LM Studio? Point BitLLM at it. Every model it lists is shared under its own id. No port forwarding, and peers reach you by relay or hole punching.

c / relay

Add a public relay

A host with inbound TCP and UDP 4001 runs --public: DHT server and relay, no DNS record. NATed nodes reserve on it alongside the seed, so capacity grows with the network.

03 design

No coordinator. No database.

A seed is a phone book entry, not a switchboard. After first contact, the network is DHT lookups, gossip, and the shortest path two peers can build.

01 / discovery

Find each other

A fresh install resolves _dnsaddr.bootstrap.bitllm.org, then asks a Kademlia DHT who serves a model. Servers gossip what they have every ten seconds.

02 / connectivity

Get through NAT

Most nodes are behind NAT or CGNAT. A relay carries the first bytes; hole punching upgrades the link to direct when the routers allow it. Everything is encrypted.

03 / inference

Stream the answer

Your gateway speaks OpenAI and Anthropic. It picks a server with a free slot, queues if all are busy, and streams tokens straight from the GPU that produced them.

04 / receipts

Count the work

Client and server both sign a receipt for token counts and a hash of the response. Receipts gossip to every node, so credits are publicly countable without a ledger server.

04 model names

A name is the model, not the machine.

If two machines announce the same name, they are interchangeable for it. The gateway uses one; if it stops answering, it tries another. That is the whole failover rule.

public weights

Use the Hugging Face id

Qwen/Qwen3.8-Flash-Next, slash and case as published. Independent hosts that serve the same repo match without a registry.

quant or fine-tune

Name the actual weights

Use the repo id of the weights, plus a suffix that says what changed: Qwen/Qwen3.8-Flash-Next-fp4-alesha. One name means one set of weights.

something new

Just serve it

Any stable id works. No registration: the node announces it, /v1/models lists it, and the dashboard lets a user pick it. A model added to your server later appears without a restart.

05 access

Invite-only, in the BitTorrent sense.

No account is needed to try the network. Membership decides who gets a free slot first, not who can join.

  1. i
    An invite gets you served on any free slot.

    Uninvited nodes are served only when a server is idle, unless its owner opens it to everyone.

  2. ii
    No daily quota by default.

    A server owner can set one, per member or for everyone.

  3. iii
    Sharing makes you a contributor.

    Never limited by quota, and 10 invites instead of 3 once your nodes have served.

Invites are signatures

An Ethereum account signs an invite; nodes gossip it. There is no membership server, and revoking an account removes everyone it invited.

The server reads the prompt

As with any inference provider. Do not send secrets. Direct peers can see your IP address; use a VPN if that matters.

Nothing is verified yet

A node can claim a model it does not serve. Auditing is opt-in and spot-check based; it is not a proof of weights. Credits have no monetary value.
